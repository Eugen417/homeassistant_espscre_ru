# What still knows a board by name

An audit of 2026-09-20, the evening a third board (Waveshare 800x480) joined the two the project started with.
Five readers went through the firmware YAML, the shared C++, the add-on, the editor and the tests, tools and
docs, looking for one thing: a capability or a size decided by a board's NAME or by a fixed number, where it
should follow from what the screen IS -- its shape, its grid, its density. Every finding was then given to a
second reader whose job was to refute it. 93 were raised, 47 survived. The ones that did not survive are not
listed; they were mostly sizes that are honestly physical, or hardware that belongs in a board file.

Read this with docs/RESPONSIVE.md, "Designing a card or a page here".

**Done since (the review of the same evening, app 0.2.93):** the page grid has one answer again. The add-on counts
every slot, row, page and tile limit on the screen's own grid (`core.Grid`, `grid_of`), the editor takes its page cap
from the same 64-tile rule and moves tiles by the screen's columns, and the layout sensor and the tile events name a
column by number on a screen that has more than two. The camera and cover offers in the editor follow the board's
picture support instead of its name, and the top bar mockup the screen's look and density. In the firmware the size
class comes from the look everywhere (`ui::large()`), `ROTATION_SUPPORTED` and `TOUCH_ROTATION` are gone, and the
Waveshare's size table is consistent with its rows. Rotation itself is still as described below. The line numbers in
this file are those of the evening it was written.

## The one to fix first: rotation

Rotation is the clearest case and the audit found it is worse than it looks.

`ROTATION_SUPPORTED` is **dead**. All three board files declare it (`cyd` false, `guition` true, `waveshare43`
true) and `${ROTATION_SUPPORTED}` is read nowhere in the tree -- only `tools/new_board.py` mentions it, to copy
it verbatim to the next board. The real switch is a line of C++ smuggled through a hook substitution:
`BOOT_ENABLED_HOOK` in `packages/boards/guition-4848s040.yaml:208` sets `runtime_tiles::rotation_supported`.
So the Waveshare declares a capability it does not have, carries the Guition's whole `APPLY_ROTATION` block as
dead code, and has no Rotation entity at all.

The owner settled the rule: **a screen may always turn 180 degrees**, because width and height are unchanged and
so the grid and the entire size table still hold; **only a square screen may turn 90 or 270**, because otherwise
the number of rows and columns that fit changes and it is really a different board with its own profile. That
makes rotation not a flag but a consequence of `DISPLAY_W == DISPLAY_H`.

Two things a rewrite must not miss, both found by the refutation pass:

- **The board's base rotation differs.** `LVGL_ROTATION` is `90` on the CYD and `0` on the other two, so core
  must apply `(base + chosen) % 360`. Passing the chosen angle straight to `set_rotation`, the way both board
  hooks do today, would send a CYD asked for 180 to 180 instead of 270 and mirror its canvas.
- **`EdgeSwipe` is configured with the logical canvas** (`DISPLAY_W`/`DISPLAY_H` after LVGL's rotation) but its
  own `rotate()` treats those as the native size, so a turned screen's edge swipe is computed against the wrong
  pair (`components/smart_display/cyd_ui.h:148` with `:186-190`).

Today the CYD cannot be turned at all, not even the half turn that costs nothing: its own board file carries a
commented-out 180 preset (`cyd-2432s028.yaml:142-176`) showing that only `LVGL_ROTATION` changes, 90 -> 270.

## The second: the page grid, in three places that disagree

The firmware derives the page from the board (`components/smart_display/runtime_model.h:40-44`):
`SLOTS_PER_PAGE = columns * rows`, `MAX_PAGES = min(64 / SLOTS_PER_PAGE, 8)`, `MAX_TILES = MAX_PAGES *
SLOTS_PER_PAGE`. The add-on fixes `SLOTS_PER_PAGE = 6`, `MAX_PAGES = 8`, `MAX_TILES = 48`
(`screen_manager/app/core.py:46,102-104`) and the editor fixes `MAX_PAGES = 8`
(`web/src/model/layout.ts:14`). On the 3 x 3 Waveshare that is three different answers to "how much fits":
63 tiles over 7 pages, 48 tiles, and 8 pages. On a 3 x 5 board the editor would offer four pages the screen
refuses.

## How to use this

Take rotation first: it is wrong today, the owner has settled the rule, and the fix deletes a dead substitution,
a hook and a board-name test in four places at once. Then the page grid, because a 3 x 3 board ships on this
branch and the firmware, the add-on and the editor already give three different answers. The rest is mostly the
same shape of problem: a table keyed by board name (alert limits, top bar geometry, camera offers), a literal
480 standing in for "the standard look", or a sentence in nine languages that names one board where the rule is
general.

A gate would have caught none of this. `tools/check_packages.py` now checks that a board's cells file matches its
grid and that no two boards claim the same word; the smallest honest additions would be that a board's declared
rotation matches its shape, and that the add-on's page arithmetic agrees with the firmware's.
